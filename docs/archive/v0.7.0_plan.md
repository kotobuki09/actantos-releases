## Goal
Turn the product into something a design partner can run: SIEM/webhook export, signed evidence export, onboarding docs, support runbooks, and two real governed workflows.

## Entry criteria
```text
- v0.6.0 tagged
- Security beta accepted
- Audit verifier works
- Self-host install works on clean machine
- At least one pilot candidate workflow selected
```

## Non-goals
```text

- Automated pilot scoring
```

### v0.7-D: Two Governed Workflow Playbooks (engineering exit)
**Owner:** A9 Pilot/Customer Workflow
**Support:** All teams

> **Strategy alignment (post-grill):** Workflow 1 (coding / Pi) is the **pilot-gating** path. Workflow 2 (MCP) is **optional proof** for product completeness, not a requirement for Design Partner Pilot #1 success. Living external pilots are tracked in `design_partner_window_plan.md`, not as a re-open of v0.7.

**Pilot workflow 1: Coding agent governance (Pi Primary Path)**
```text
- Agent reads repo files
- Agent edits safe file
- Agent attempts .env read -> deny
- Agent runs tests -> allow
- Agent attempts git push --dry-run -> approval_required
- Human approves
- Command executes in sandbox
- Evidence package exported
```

**Pilot workflow 2: MCP tool governance (MCP Optional Path)**
```text
- Register MCP server
- tools/list filtered by policy
- safe tool call allowed
- mutating tool call requires approval
- manifest drift introduced
- drifted tool blocked until approved
- SSRF attempt denied
- Evidence package exported
```

**Tasks:**
```text
v070-WORKFLOW-001 Execute pilot workflow 1: Coding agent governance (demo/playbook)
v070-WORKFLOW-002 Execute pilot workflow 2: MCP tool governance (demo/playbook)
```

**Engineering evidence gate (v0.7):**
```text

- agent/session identity
- policy bundle hash
- decisions
- approvals
- tool results
- redacted previews

Reproducible from onboarding guide without engineer-only DB steps.
```

**Done when (v0.7 engineering):**

- No manual DB edits or engineer-only steps needed
