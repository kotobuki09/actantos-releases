# v0.3.0 — MCP Hardening Beta

> **Status:** ✅ **COMPLETE** (historical). MCP gateway remains **supported but optional** for Design Partner Pilot success (Pi Primary Path). Do not open new tickets here unless a written Escape Hatch requires it.
>
> **Prerequisites:** Read `00_global_rules_and_teams.md` first for team lanes, global rules, and ticket format.
>
> **Canonical next work:** `v1.0.0_plan.md` then `design_partner_window_plan.md`. See ADR `0004-pilot-sequencing-pi-primary.md`.

## Goal
Harden the existing MCP gateway into a credible beta: registry, manifest approval UX, SSRF matrix, policy filtering, conformance tests, no token passthrough.

## Entry criteria
```text
- v0.2.0 tagged
- Redaction works everywhere
- Slack approval stable
- Current MCP baseline still passes
- Manifest drift currently denies or forces approval
```

## Non-goals
```text
- Fully automated drift resolution
- External manifest registries
- MCP protocol extensions beyond spec
- Credential broker / vault integration
```

**Owner:** A4 MCP Gateway
**Support:** A1 Core API/DB, A7 Console/UI

**Tasks:**
```text
v030-MCP-001 Add MCP server registry API
- POST /v1/mcp/servers
- GET /v1/mcp/servers
- GET /v1/mcp/servers/:id
- PATCH /v1/mcp/servers/:id
- DELETE/disable server

v030-MCP-002 Add server fields
- name
- transport
- upstream_url
- server_identity_hash
- status
- owner_user_id
- created_at

v030-MCP-003 Add registry UI
- list servers
- show status
- show approved baseline
- show pending drift versions
- disable server

v030-MCP-004 Add registry audit events
- mcp_server_registered
- mcp_server_disabled
- mcp_tool_manifest_changed
- mcp_tool_approved
```

**Done when:**
```text
- Admin can register upstream MCP server
- Drifted MCP tool appears as pending
- Disabled MCP server cannot be called
- All registry actions create audit events
```

### v0.3-B: Manifest Drift Approval UX
**Owner:** A4 MCP Gateway
**Support:** A7 Console/UI, A5 Security/QA

**Tasks:**
```text
v030-DRIFT-001 Persist manifest versions
- tool_name
- schema_hash
- description_hash
- full manifest JSON
- approved boolean
- created_at

v030-DRIFT-002 Add diff renderer
- old tool description
- new tool description
- old schema hash
- new schema hash
- risk warning for changed description

v030-DRIFT-003 Add approval action
- approve pending version
- set as baseline
- audit approval actor
- reject pending version

v030-DRIFT-004 Enforce drift behavior
- tools/list hides drifted tool or marks unavailable
- tools/call denies with manifest_drift/schema_hash_mismatch
- no forwarding until approved
```

**Tests:**
```text
- unchanged manifest -> allowed path
- changed schema -> denied/pending approval
- changed description only -> denied/pending approval
- approval promotes new baseline
- rejected manifest remains blocked
```

**Done when:**
```text
- Drifted tools are blocked until approved
- Approval promotes new baseline
- Rejected manifests remain blocked
- All drift actions are auditable
```

- 10.0.0.0/8

- 192.168.0.0/16

v030-SSRF-005 Test IPv6 local/internal
- ::1
- fe80::/10
- fc00::/7

v030-SSRF-006 Test DNS tricks
- hostname resolving to private IP

**Done when:**
```text

- Denial reason is stable and auditable
- No upstream request is sent on SSRF deny
```
