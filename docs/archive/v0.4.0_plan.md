# v0.4.0 — Self-Host Alpha

> **Status:** ✅ **COMPLETE** (historical). Self-host install is part of the Quiet Open-Core free surface. Do not open new tickets here.
>
> **Prerequisites:** Read `00_global_rules_and_teams.md` first for team lanes, global rules, and ticket format.
>
> **Canonical next work:** `v1.0.0_plan.md` then `design_partner_window_plan.md`.

## Goal
Make ActantOS installable and operable as a production-like single-tenant self-host package.

## Entry criteria
```text
- v0.3.0 tagged
- MCP hardening tests pass
- Basic console works
- Current Docker Compose path works locally
```

## Non-goals
```text
- Multi-tenant SaaS orchestration
- Kubernetes Helm charts
- OIDC / SSO (admin API key is sufficient for alpha)
- Automated scaling
```

---

## Workstreams

### v0.4-A: Production-like Compose
**Owner:** A8 DevOps/CLI
**Support:** A1 Core API/DB

**Tasks:**
```text
v040-COMP-001 Create docker-compose.selfhost.yml
- actantosd
- postgres
- optional console service
- optional MCP gateway service if separate
- network isolation
- named volumes

v040-COMP-002 Add .env.example
- ACTANTOS_PORT=3100
- DATABASE_URL
- ADMIN_API_KEY or JWT secret
- SLACK config optional
- redaction config
- feature flags

v040-COMP-003 Add production-like Dockerfile
- non-root user
- minimal image
- healthcheck
- pinned dependency versions

v040-COMP-004 Add startup validation
- fail if admin secret missing
- fail if weak secrets in non-dev mode
- fail if DB migration pending and auto-migrate disabled

v040-COMP-005 Add clean-machine smoke test
```

**Done when:**
```text
- Fresh clone + .env + docker compose starts system
- Daemon default port is 3100 unless explicitly overridden
- Health/readiness endpoints report correctly
- Startup rejects weak/missing admin secrets in non-dev mode
```

### v0.4-B: Admin Auth/API Keys

**Support:** A5 Security/QA

**Protected routes:**
```text
- approval decide routes

- policy bundle routes
- MCP registry admin routes
- evidence export routes

```

**Tasks:**
```text
v040-AUTH-001 Define admin auth mode
- MVP: admin API key
- optional JWT support if already simple

v040-AUTH-002 Add auth middleware
- public health endpoint allowed
- protected admin endpoints require auth
- invalid/missing auth -> 401/403

v040-AUTH-003 Add audit events for admin actions
v040-AUTH-004 Add tests for unauthorized access
v040-AUTH-005 Add docs for key rotation/manual replacement
```

**Done when:**
```text
- Unauthorized admin requests reject with 401/403
- Authorized requests work
- Approval/kill-switch cannot be called anonymously
- Admin actions create audit events
```
