# v0.5.0 — Policy & Budget Beta

> **Status:** ✅ **COMPLETE** (historical). Follow-on policy work in the pilot window is limited to **Balanced** (default) and **Strict** (opt-in) coding templates and pilot-blocking fixes only. Do not open platform policy features here.
>
> **Prerequisites:** Read `00_global_rules_and_teams.md` first for team lanes, global rules, and ticket format.
>
> **Canonical next work:** `v1.0.0_plan.md` then `design_partner_window_plan.md`. See `CONTEXT.md` policy postures.

## Goal
Move from fixed demo policy into policy/budget operations: upload/version/rollback Cedar bundles, enforce budgets/rate limits, and lock dry-run onboarding semantics.

## Entry criteria
```text
- v0.4.0 tagged
- Self-host install works
- Admin auth protects policy/admin routes
- OpenAPI and compatibility tests exist
```

## Non-goals
```text
- Complex multi-tenant budget pooling
- Visual policy builder / marketplace
- Custom policy languages (Cedar only)
- Budget billing integration
```

## Workstreams

### v0.5-A: Policy Bundle Upload/Version/Rollback
**Owner:** A2 Policy/Budget
**Support:** A1 Core API/DB, A7 Console/UI

**Tasks:**
```text
v050-POL-001 Add policy bundle upload API
- POST /v1/policy-bundles
- validate source
- compute source_hash
- store inactive by default

v050-POL-002 Add policy validation
- Cedar syntax validation
- basic semantic smoke test
- required default permits check if demo policy
- reject invalid policy

v050-POL-003 Add activation route
- POST /v1/policy-bundles/:id/activate
- deactivate previous active bundle atomically
- audit policy activation

v050-POL-004 Add rollback route
- activate previous known-good bundle
- audit rollback actor and reason

v050-POL-005 Add policy bundle UI
- list versions
- show active
- upload
- validate errors
- activate/rollback

v050-POL-006 Add policy regression test suite
```

**Done when:**
```text
- Invalid Cedar never becomes active
- Activation is atomic
- Rollback restores previous behavior
- Decision records include policy_bundle_id/hash
```

```text

v050-BUD-005 Add rate-limit tests
v050-BUD-006 Add budget admin API
v050-BUD-007 Add simple budget UI
```

**Tests:**
```text
- below limit -> allow path continues
- equal/above limit -> deny budget_exceeded

- dry_run does not consume budget unless explicitly configured
```

**Done when:**
```text
- Budget limits correctly reject excess calls
- Idempotency prevents double charge
- Budget denial is auditable
```


**Tests:**
```text

- dry_run result cannot claim executed
```

**Done when:**
```text
- Dry-run pilot can show what would happen without executing anything
- No decision_token is issued in dry_run mode
- No approval token is consumed in dry_run mode
```
